# Реализация мягкого удаления и восстановления доступа

## 📋 Описание

Система мягкого удаления позволяет приостанавливать доступ пользователей к каналу при истечении подписки без фактического удаления их из канала. При повторной оплате доступ автоматически восстанавливается.

## 🎯 Реализованные функции

### 1. Мягкое удаление пользователя
**Когда срабатывает:** Автоматически при истечении подписки (каждые 6 часов проверка)

**Что происходит:**
- ✅ Пользователь помечается в БД как удаленный (`is_banned = TRUE`)
- ✅ Доступ к контенту приостанавливается (`has_access = FALSE`)
- ✅ Пользователь **НЕ удаляется** физически из канала
- ✅ Отправляется уведомление о необходимости продления подписки
- ✅ Действие логируется в таблицу `logs`

**Код:** `bot.js` → метод `kickUserFromChannel()`

```javascript
// Мягкое удаление - только пометка в БД
await this.databaseService.softDeleteUser(userId);
```

### 2. Автоматическое восстановление доступа
**Когда срабатывает:** При получении успешной оплаты через webhook от Prodamus

**Что происходит:**
- ✅ Проверяется, был ли пользователь помечен как удаленный
- ✅ Если да - снимается флаг бана (`is_banned = FALSE`)
- ✅ Восстанавливается доступ (`has_access = TRUE`)
- ✅ Создается новая подписка на 30 дней
- ✅ Отправляется уведомление о восстановлении доступа
- ✅ Отправляется invite-ссылка для доступа к каналу
- ✅ Действие логируется в таблицу `logs`

**Код:** `bot.js` → метод `restoreChannelAccess()`

```javascript
// Проверка и восстановление
const isBanned = await this.databaseService.isUserBanned(userId);
if (isBanned) {
    await this.restoreChannelAccess(userId, paymentId);
    await this.grantChannelAccess(userId);
}
```

### 3. Обновления базы данных

Добавлено новое поле в таблицу `users`:
```sql
is_banned BOOLEAN DEFAULT FALSE
```

Новые методы в `DatabaseService`:
- `softDeleteUser(telegramId)` - мягкое удаление пользователя
- `restoreUser(telegramId)` - восстановление пользователя
- `isUserBanned(telegramId)` - проверка статуса бана

## 🔄 Процесс работы

### Сценарий 1: Истечение подписки

1. Пользователь оплатил доступ к каналу → получил подписку на 30 дней
2. За 3 дня до истечения → получает напоминание о продлении
3. Подписка истекла → автоматическое мягкое удаление:
   - Статус в БД меняется на `is_banned = TRUE`
   - Пользователь получает уведомление со ссылкой на оплату
   - Пользователь остается в канале, но помечен как неактивный

### Сценарий 2: Повторная оплата

1. Пользователь с истекшей подпиской оплачивает доступ
2. Webhook от Prodamus получает информацию об оплате
3. Система автоматически:
   - Проверяет статус пользователя
   - Обнаруживает `is_banned = TRUE`
   - Вызывает `restoreChannelAccess()`:
     - Снимает флаг бана
     - Восстанавливает доступ
     - Создает новую подписку
   - Отправляет уведомление о восстановлении
   - Предоставляет invite-ссылку

## 📊 Логирование

Все действия логируются в таблицу `logs`:

**Мягкое удаление:**
```javascript
{
  action: 'soft_delete',
  details: 'Пользователь помечен как удаленный из-за истечения подписки (мягкое удаление)'
}
```

**Восстановление:**
```javascript
{
  action: 'access_restored',
  details: 'Доступ восстановлен после оплаты (payment_id: XXX)'
}
```

## 🧪 Тестирование

### Проверка мягкого удаления

1. Создайте тестовую подписку с коротким сроком действия
2. Дождитесь истечения подписки
3. Проверьте в БД: `SELECT * FROM users WHERE telegram_id = XXX`
   - Должно быть `is_banned = 1`, `has_access = 0`
4. Проверьте логи: `SELECT * FROM logs WHERE telegram_id = XXX AND action = 'soft_delete'`

### Проверка восстановления доступа

1. Для пользователя с `is_banned = 1` произведите оплату
2. Webhook обработает платеж
3. Проверьте в БД:
   - `is_banned = 0`, `has_access = 1`
   - Новая запись в `subscriptions` с `is_active = TRUE`
4. Проверьте логи: `SELECT * FROM logs WHERE telegram_id = XXX AND action = 'access_restored'`

## 🔍 SQL-запросы для мониторинга

### Список забаненных пользователей:
```sql
SELECT 
    telegram_id, 
    username, 
    first_name, 
    updated_at 
FROM users 
WHERE is_banned = TRUE
ORDER BY updated_at DESC;
```

### История восстановлений доступа:
```sql
SELECT 
    l.telegram_id,
    u.username,
    l.action,
    l.details,
    l.created_at
FROM logs l
JOIN users u ON l.telegram_id = u.telegram_id
WHERE l.action = 'access_restored'
ORDER BY l.created_at DESC;
```

### Статистика по мягким удалениям:
```sql
SELECT 
    COUNT(*) as total_soft_deletes,
    DATE(created_at) as delete_date
FROM logs
WHERE action = 'soft_delete'
GROUP BY DATE(created_at)
ORDER BY delete_date DESC;
```

## ⚠️ Важные замечания

1. **Не используется реальный бан** - пользователи остаются в канале, только помечаются как неактивные в БД
2. **Автоматическое восстановление** - при повторной оплате система сама снимает все ограничения
3. **Полная история** - все действия записываются в логи для аудита
4. **Бесшовный опыт** - пользователь не замечает технических деталей, только получает уведомления

## 🚀 Преимущества мягкого удаления

- ✅ Пользователь не теряет историю сообщений в канале
- ✅ Простое восстановление без необходимости повторного приглашения
- ✅ Сохранение истории действий пользователя
- ✅ Нет риска блокировки бота за частые баны
- ✅ Лучший пользовательский опыт
