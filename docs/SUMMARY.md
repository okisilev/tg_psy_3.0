## 🔄 Как это работает

### Сценарий 1: Истечение подписки (Мягкое удаление)
```
Подписка истекла
    ↓
Система помечает пользователя как is_banned = TRUE в БД
    ↓
Доступ блокируется (has_access = FALSE)
    ↓
Пользователь получает уведомление со ссылкой на оплату
    ↓
❗ ВАЖНО: Пользователь НЕ удаляется из канала!
```

### Сценарий 2: Повторная оплата (Автоматическое восстановление)
```
Пользователь оплачивает доступ
    ↓
Webhook получает данные от Prodamus
    ↓
Система проверяет is_banned пользователя
    ↓
Если is_banned = TRUE:
    - Снимается флаг бана (is_banned = FALSE)
    - Восстанавливается доступ (has_access = TRUE)
    - Создается новая подписка на 30 дней
    - Отправляется уведомление о восстановлении
    - Отправляется invite-ссылка для канала
```

## 🔍 Мониторинг

### Забаненные пользователи:
```sql
SELECT telegram_id, username, is_banned, has_access, updated_at 
FROM users 
WHERE is_banned = TRUE;
```

### История мягких удалений:
```sql
SELECT l.telegram_id, u.username, l.action, l.created_at
FROM logs l
JOIN users u ON l.telegram_id = u.telegram_id
WHERE l.action = 'soft_delete'
ORDER BY l.created_at DESC;
```

### История восстановлений:
```sql
SELECT l.telegram_id, u.username, l.action, l.created_at
FROM logs l
JOIN users u ON l.telegram_id = u.telegram_id
WHERE l.action = 'access_restored'
ORDER BY l.created_at DESC;
```

## ✨ Преимущества реализации

1. **Мягкое удаление** - пользователь остается в канале, только блокируется доступ
2. **Автоматическое восстановление** - при оплате доступ восстанавливается автоматически
3. **Полное логирование** - все действия записываются в БД
4. **Лучший UX** - пользователь не теряет историю сообщений
5. **Нет риска блокировки бота** - не используется реальный бан Telegram
6. **Гибкость** - легко отследить статус любого пользователя
